We're not trying to co-evolve two randomly initialized models. You're using an already-trained generator population and introducing a learned semantic reward model.

I'd approach it in two distinct phases.

## **Phase 1: Train the discriminator(s)**

Freeze all existing generators.

**Training data**

- Original task context
- Correct reference implementation
- Existing swarm outputs
- Synthetic hard negatives

**Discriminator training**

**Contextual ranking**

Learn to distinguish implementations that belong in the given context from those that don't.

**Validation**

Hold out entire tasks, not merely candidate implementations from known tasks.

I'd pay particular attention to preventing data leakage. If the discriminator sees the same underlying function with slightly different implementations in training and validation, its apparent generalization could be misleading.

I'd also include hard negatives generated by your existing swarm. Your logs are excellent material for this because they contain realistic examples of semantic failure.

## **Phase 2: RL against the discriminator**

Now freeze the discriminator initially and use it to provide rewards to your existing generators.

**Candidate implementations**

**Frozen discriminator(s)**

- Semantic relevance

**RL reward**

Optimize generator policies against learned reward

Repeat across coding tasks

One important recommendation: I'd initially keep the discriminators frozen during RL. Otherwise, the reward landscape changes while the generators are learning, making it harder to understand whether improvements come from better generation or shifting evaluation criteria.

## **Three experiments I'd prioritize**

| Experiment                        | Question                                                               |
| --------------------------------- | ---------------------------------------------------------------------- |
| D1: Discriminator accuracy        | Can it distinguish contextual correctness?                             |
| G1: RL with discriminator reward  | Can existing generators improve without supervised retraining?         |
| G2: RL with discriminator + tests | Does combining semantic and behavioral rewards improve generalization? |

## **One potentially important detail: reward calibration**

Don't simply use the discriminator's raw confidence as the reward.

A discriminator can become overconfident, especially on unfamiliar code. I'd use pairwise ranking, calibration against held-out examples, and reward normalization.

I'd also retain compilation and behavioral tests as independent checks, rather than allowing the discriminator to become the sole authority.
