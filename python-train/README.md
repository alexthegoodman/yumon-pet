# Yumon Pet - PyTorch Sparse MoE Training

PyTorch / `uv` implementation of the **Yumon Pet** language brain. Switched from Burn to PyTorch for faster, more scalable training on modern NVIDIA GPUs (including RunPod deployment).

Features:
- **Genuine Sparse MoE**: Dropless top-k mixture of experts with SwiGLU activation, Switch-style auxiliary load balancing loss, and router z-loss.
- **Flash Attention**: Built-in PyTorch scaled dot-product attention (`F.scaled_dot_product_attention`, causal).
- **Rotary Position Embeddings (RoPE)**: High-resolution positional encoding on queries and keys.
- **Fast Binary Dataloader**: Directly streams and decompresses the `samples.bin` binary cache generated by the Rust project in seconds, eliminating any need to rewrite dataset loaders.
- **Dynamic Batch Trimming**: Crops unused padding columns per batch for maximum throughput.
- **Easily Configurable**: All hyperparameters are adjustable via command-line arguments, dataclass configs, or environment variables.
- **RunPod Ready**: Includes Dockerfile targeting RunPod PyTorch CUDA 13 with automated build-time preflight verification.

## Quick Start

### 1. Install & Test

Using [`uv`](https://docs.astral.sh/uv/):

```bash
cd yumon-pet/python-train
uv run python test_model.py
```

### 2. Start Training

To train with default hyperparameters:

```bash
uv run python train.py --tokenizer-path "../training-cache/yumon_talk_tokenizer" --data-path "../training-cache/yumon_talk_samples.bin"
```

To train with custom hyperparameters from CLI:

```bash
uv run python train.py \
  --embed-dim 256 \
  --n-layers 12 \
  --attn-heads 8 \
  --ff-dim 1024 \
  --num-experts 4 \
  --top-k 1 \
  --batch-size 16 \
  --epochs 15 \
  --first-lr 1e-4 \
  --last-lr 1e-5
```

### 3. Generate Replies from Trained Checkpoint

Interactive chat mode:

```bash
uv run python generate.py --checkpoint checkpoints/best_model.pt
```

Single prompt mode:

```bash
uv run python generate.py \
  --checkpoint checkpoints/best_model.pt \
  --prompt "Tell me about yourself." \
  --temperature 0.8 \
  --top-k 40
```

## Hyperparameter Reference

All hyperparameters can be adjusted in Python via `TrainingConfig` in `train.py` or via CLI flags:

| Hyperparameter | Flag | Default | Description |
|---|---|---|---|
| `embed_dim` | `--embed-dim` | `256` | Transformer hidden dimension (e.g. 256, 512, 1024) |
| `n_layers` | `--n-layers` | `12` | Number of decoder layers |
| `attn_heads` | `--attn-heads` | `8` | Number of attention heads |
| `ff_dim` | `--ff-dim` | `1024` | SwiGLU expert intermediate dimension |
| `num_experts` | `--num-experts` | `4` | Number of MoE experts per layer (e.g. 4, 8, 16) |
| `top_k` | `--top-k` | `1` | Number of experts routed per active token |
| `max_seq_len` | `--max-seq-len` | `256` | Maximum token sequence length |
| `batch_size` | `--batch-size` | `16` | Batch size |
| `epochs` | `--epochs` | `15` | Total training epochs |
| `first_lr` | `--first-lr` | `1e-4` | Initial learning rate |
| `last_lr` | `--last-lr` | `1e-5` | Final learning rate (linear decay) |
| `weight_decay` | `--weight-decay` | `0.01` | AdamW weight decay |
| `aux_loss_weight` | N/A | `0.01` | Weight for MoE load-balancing loss |
| `z_loss_weight` | N/A | `0.001` | Weight for router z-loss |
| `precision` | `--precision` | `bf16` | Training precision (`bf16`, `fp16`, `fp32`) |
| `eval_every` | `--eval-every` | `500` | Batches between evaluation and best model checkpoint saves |
| `sample_log_file` | `--sample-log-file` | `sample_outputs.txt` | TXT log file in checkpoint directory recording sample prompt outputs on checkpoint saves |
| `generate_samples` | `--no-samples` | `True` | Whether to generate and log sample text outputs during training |
| `checkpoint_dir` | `--checkpoint-dir` | `checkpoints` | Directory to save checkpoints (defaults to `/workspace/checkpoints` on RunPod) |

## Generating `samples.bin` from Rust

You do not need to rewrite any of the complex dataset loading logic in Python. The Rust project prepackages and verifies all corpora into a compact zstd binary cache:

```bash
# Run from yumon-pet/
cargo run --release --bin cache_samples -- \
  --output training-cache/samples.bin \
  --tokenizer yumon_bpe \
  --stage language \
  --max-seq-len 256
```

The Python dataloader (`dataloader.py`) automatically streams and decompresses `samples.bin` in under a second for the entire ~177k dataset.

## RunPod Deployment (Docker)

### 1. Build and Push the Docker Image

From `yumon-pet/python-train`:

```bash
# Ensure samples.bin is present in training-cache/ or copy it:
mkdir -p training-cache
cp ../training-cache/samples.bin training-cache/samples.bin

docker build -t your-username/yumon-pet-train:latest .
docker push your-username/yumon-pet-train:latest
```

### 2. Deploy on RunPod

1. Deploy a GPU pod (e.g., RTX 4090, A100, or H100) using your Docker image.
2. Mount your RunPod Network Volume to `/workspace`.
3. Checkpoints (`best_model.pt`, `checkpoint_epoch_*.pt`, `config.json`) automatically save to `/workspace/checkpoints/` and persist across pod terminations.
4. The container starts training automatically with `python3 train.py`.
